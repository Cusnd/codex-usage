## 1. 产品范围与正常使用流程

| 项目 | 当前要求 |
| --- | --- |
| 使用主体 | 单用户、同一个 GitHub 登录身份对应的云端空间；设备作为独立采集来源接入 |
| 设备数量 | 支持多台设备及任意设备子集；文档中的 A／B 只是示例，不是两台上限 |
| 平台 | 保留 Windows、macOS 支持范围，并加入 Linux 采集、安装／运行和设置支持；各平台完成情况必须实测 |
| 两种入口 | 保留现有本机面板，本机入口继续查看本机；云端入口查看已同步设备，支持分别／融合展示 |
| 设备端形态 | 沿用现有本机面板及后台采集方式，不新增单独的轻量采集模式 |
| 功能延续 | 沿用现有总览、趋势／比较、项目、Session／轮次、Agent、成本、账号与设置的业务口径，将设备范围贯通相关页面、列表及下钻 |
| 当前优先级 | 先完成功能、数据处理和完整链路，UI 样式后谈；按 OpenAI 账号筛选任务消耗继续列 TODO |

正常使用流程：

1. 用户在各台电脑完成现有安装、设置与绑定。每台设备自主采集、增量处理并通常实时上传，关掉云端页面不影响采集。
2. 用户登录云端面板，取得云端保存的结果。设备离线或关机后，已经上传的历史仍然可查。
3. 访问端第一次同步加载活跃任务和最近 30 天；第二次同步补齐全部历史。自动和手动触发共用进度，用户可以在第一轮后直接点击刷新进入全量同步。
4. 全量复用已有数据；初始化之后按变化更新。访问端自动间隔沿用原有设置，手动刷新沿用原有使用逻辑。
5. 用户选择一台、多台或全部设备查看用量；在云端编辑项目组织和持久设置，云端保存后在后续访问中恢复。

两轮加载只控制访问端取得和缓存云端数据，不延迟采集端上传历史。第二轮只能覆盖云端当时已收到的数据，尚在上传的设备历史继续补入。在线优先，浏览器缓存已解析结果；独立、完整的离线分析引擎不列为本轮必要功能。

## 2. 统计、设备来源与项目组织

### 2.1 同一消耗只计一次，按实际执行设备查看

- 同一消耗全局去重；设备筛选依据实际执行来源，上传设备与执行设备分别记录。
- A 产生 100，历史复制到 B 后 B 新增 20，结果应为全局 120、A 100、B 20。同一个 Session 的后续新增消耗必须保留。
- 采集器主动附加并保留持久身份、来源和上下文，原始 Codex 文件只读。不能仅凭相同时间、Token、标题或目录名判定为同一消耗。
- 只有确实缺少原始来源且无法恢复的旧历史，才保留全局用量、标记设备未知，并允许带“用户指定”标记的批量归属；正常可确定来源的记录按实际设备统计。
- 所有页面使用一致的有效事件和筛选口径；任务／轮次／项目数量按对应身份去重，不能直接相加重叠的分组计数。缺失值、修订、fork 继承与 Agent 层级继续按明确的业务规则处理。

### 2.2 项目自动组织与人工选择

| 情形 | 结果 |
| --- | --- |
| Git 项目 | 按仓库组织；可靠的主要仓库身份可证明跨设备独立克隆属于同一仓库 |
| 无 Git 的已保存项目 | 沿用 App 项目及根目录；缺少映射时保留待解析状态，不伪造项目身份 |
| 独立对话 | 按 Session 身份组织 |
| 同一可信 Session 连接多个来源项目 | 自动合并整个项目及其中全部会话，关联可以传递 |
| 同一远程仓库的独立克隆 | 确认身份后自动合并，即使没有共享 Session；任意共同 remote、fork 上游、相同名字不能单独作为依据 |
| 工作路径变化 | 沿用此前按新来源项目处理的约定；可靠同仓库／同 Session 关系或人工操作仍可合并，不单凭路径相似自动延续 |
| 人工合并／拆分 | 持久保存，优先于自动关系；后续同步、重试、重建不得覆盖人工拆分 |
| 新项目 C 同时连接人工拆开的 A／B | A／B 保持拆分，C 暂时独立；不通过 C 间接重新合并，也不要求另设待归属处理流程 |
| 项目名称 | 人工名称优先；否则稳定选用来源名称，原路径、原项目和设备仍可查看 |
| 自动合并说明 | 可以查看合并依据；此前提出的名称旁说明入口保留，具体样式后续处理 |

项目组织改变不改写原始消耗，也不改变全局 Token 总量。第一版完成逻辑项目合并和拆分，额外多标签集合后置。

### 2.3 云端保存人工修改和设置

采用单用户统一云端空间。项目组织、人工名称、归属修改以及持久设置保存到云端；重新登录或换浏览器访问时取得云端保存结果。云端页面中的时区、成本口径、同步间隔等持久设置不能仅停留在当前浏览器。

人工操作可以先在页面反馈，随后保存云端；是否成功以云端确认结果为准，失败提供正常的错误与重试反馈。采集端上报事实和元数据，不作为项目组织的编辑端，解析更新不得覆盖人工选择。

第一版不设计复杂的多访问端编辑冲突合并、离线协作队列或冲突选择界面。普通请求保存与多采集端并发入库的一致性仍由实现处理。悬浮、展开等临时交互不属于持久设置；设备本机路径和采集进程配置继续由本机管理。

## 3. 采集、云端与访问端的职责

当前架构方向如下；具体协议、引擎和服务组合见第 7 节的实现方案任务。

```text
多台设备：原始日志 → 采集与必要字段提取 → 本机持久待发批次
    → 云端接收、持久保存、业务解析、去重与关系整理
    → 一致的有效事件、索引和汇总
    → 访问端按设置同步已解析结果 → 浏览器缓存、查询和展示

现有本机面板继续使用本机数据；人工组织和云端持久设置保存到云端。
```

- 采集端理解输入格式、保留业务所需字段与上下文，提供来源信息和可恢复的待发数据；云端承担跨来源业务处理，浏览器使用已解析结果。
- 采集器与解析器分开职责，复用明确的语义契约；为压缩体积不能丢掉旧版累计记录、标题、关系或修订所必需的信息。
- 新增优先及时处理，历史补传持续取得进展；无变化时避免重新扫描、解析和传输全部有效历史。
- 重传同一批次不产生重复消耗。已接收、已应用可查、访问端已取得是不同阶段，页面同步状态应能反映实际进展。
- 多台采集端可以同时上报；更新有效事件及相关统计要保持一致。重建期间继续提供上一份完整结果，新结果完整后切换。
- 云端和访问端不远程要求采集电脑执行采集、补传、额度读取或本机配置操作。云端保存暂停／撤销状态属于上传管理，访问端刷新仅读取云端已有数据。

以上是设计约束；现有原型尚未完成全部产品接入，不能标记为已实现。

## 4. 账号额度、设备管理与恢复

### 4.1 共享额度

同一个 OpenAI 账号只显示一组共享额度，不能按设备相加或重复展示。在线采集端自主代读并上报，云端统一选择有效结果；不由 Cloudflare 托管 OpenAI 登录凭据自行读取。

查看 A 的设备用量时，若同账号 B 有更新的有效额度，仍可以采用 B 的结果。来源失败不清空其他来源的成功值；所有来源不可用时保留最后成功数据及其时点。日志用量、额度与官方每日历史保持各自含义，不要求数值相等。

**本稿采用的默认设计：** 额度区的账号列表独立于设备用量筛选，显示该云端空间的账号；选定账号的有效读取来源不受当前设备筛选限制。共享额度与来源不受限是已确认规则，账号列表的具体筛选交互是实现选择，不再列为用户待答问题。

### 4.2 设备管理

| 操作 | 已确认行为 |
| --- | --- |
| 暂停同步 | 暂停该设备全部云端上报，本地采集按本机设置继续；恢复后补传用量，额度重新取得当前值 |
| 撤销设备 | 停止该设备继续向当前云端空间上传，已保存历史按原有保留行为处理 |
| 删除设备历史 | **直接删除这个设备上传的全部历史**，包括其上传的用量及账号历史／快照；以上传来源确定范围 |
| 保留本机入口 | 继续提供现有本机面板，不新增单独的轻量采集模式 |
| 重装／重新登录 | 通过同一 GitHub 身份恢复访问原云端空间、历史与设置，并按正常流程重新绑定／接续设备 |

删除某上传设备的数据，不扩大为“删除该设备实际执行、但由其他设备上传的全部消耗”。同一事件若仍有其他设备上传的有效来源，可继续出现在融合结果中；应重算受影响结果。删除云端历史不删除本机原始文件。删除确认和旧上传请求之间的一致性由实现方案处理，沿用当前撤销旧上传身份防止删除后立即回写的基本行为。

GitHub 身份证明用户对云端空间的所有权；设备标识用于区分实际采集来源，不能因为同一 GitHub 登录就把所有设备合成一台。恢复采用正常登录和绑定流程，第一版不增加专门处理设备克隆的复杂产品流程。

## 5. 数据保留、格式变化与迁移

云端持续保存有效结构化历史、必要的身份与来源、人工组织和持久设置，直到用户主动删除。采集文件消失或设备离线不自动删除已保存历史。

**不增加为了未来修正规则而长期保存的独立重放证据／原始投影档案。** 输入格式变化时，适配采集器和解析器，重新采集并重新入库。待发送、待确认或待应用批次的临时持久保存仍服务当前可靠同步，完成后可按实现需要回收。

重新解释原始格式依赖仍可读取的本机源数据；已有云端有效历史和人工修改继续保留，新版本可用后再切换。不能先清空唯一历史，再等待设备补齐。重新解析可以修订已存在的数据，但不会借此撤销人工项目组织。

旧设备、旧协议和旧缓存迁移沿用用户接受的方向：不直接清空或重复导入，明确兼容窗口、升级提示与一致切换。具体版本、期限和数据库布局由实现方案给出，不需要继续逐项询问内部参数。

## 6. 第一版收敛范围

本次明确减少或后置的内容：

- 复杂的多浏览器人工编辑冲突策略和离线协作界面。
- 一个逻辑项目同时属于多个自定义标签集合。
- 独立轻量采集模式。
- 缓存容量专项设置、配额选择、复杂淘汰策略等独立产品设计；普通读写失败按正常错误处理。
- 独立长期重放档案，以及仅为该档案引入的额外云存储。
- 专门的设备克隆／身份遗失分支流程。

此前未成为根目标要求的团队权限、公开分享、跨用户合并、远程控制采集电脑和完整离线分析系统，继续不主动扩展。

## 7. 实现方案与验收

### 7.1 可以直接设计的工程事项

### 7.3 性能证据边界

已测得的主要分段结果：

| 阶段 | 结果及输入 | 边界 |
| --- | --- | --- |
| 新采集器全量 | 约 698.890 MB 真实日志，上传包就绪中位 3.475 秒，3 次 | 不含上传、云端和页面 |
