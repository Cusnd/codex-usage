# 完全在线云端页面：实施与本地验收

2026-09-13。状态：**代码已实施，本地验证通过，尚未部署线上**。继续使用 `codex/performance-baseline-20260912`，保留此前性能工作的未提交改动。本轮未 commit、push、部署、修改远端数据库或执行完整 CI。

## 需求与实现

用户明确选择完全在线，不需要浏览器持久离线缓存。网页现在取得当前页面所需的统计与标签；完整历史、跨设备去重和精确计算仍由云端负责。采集器上传与本地入口保持原有职责。

浏览器生产代码已移除 recent/full/delta 镜像、manifest/entities/changes 消费、逐实体摘要校验、IndexedDB staging、持久 DTO 和覆盖提升状态。9 个旧浏览器实现文件及其测试/脚本已保存在[独立实验归档](../../experiments/legacy-browser-mirror-20260913/README.md)，不再处于生产模块图中。归档自己的 51 项测试证明历史实验仍可运行，不算新实现的验收。

`POST /api/v3/view` 返回固定读取版本、设置、到期时间与读取标识，随后页面查询并发使用这个版本；续期保留原范围与设置。该初始化在无设备筛选的 D1 定向测试中只有 3 条元数据 SQL，不枚举实体、不计算完整覆盖或实体数量。设置由读取上下文直接提供。HTTP 适合当前按需查询；没有引入 WebSocket、R2 或另一套缓存协议。

主要入口：

- [在线适配器](../../modules/web/adapters/cloud.ts)：读取身份、版本验证、续期、共享在途请求与取消。
- [当前页刷新](../../modules/web/data/cloud-refresh.ts)：将当前已显示的查询准备好，全部成功后公开新版本；同版本刷新复用原查询键。
- [云端 provider](../../modules/web/data/cloud-provider.tsx)：内存生命周期、刷新间隔、删除失效与页面身份边界。
- [缓存退出](../../modules/web/adapters/legacy-cache.ts)：只删除本应用旧数据库和旧身份回退键，不创建新的统计数据库。

普通有效读取遇到暂时网络错误时可以保留上次完整结果。删除版本变化或服务端明确撤销旧读取时立即清空旧页，不能用“失败保留”继续展示删除前内容。云端趋势直接使用查询结果，不保留独立的旧曲线。正常刷新保留设置草稿和管理页选择；身份、设备范围和删除失效时清理旧请求及组件状态。设置保存后的读取必须在写入之后开始；刷新时钟也正确推进跨午夜的滚动日期。

## 浏览器基线与复测

使用 CUA 操作同一内置浏览器、同一 viewport 的完整 UI；后端为本地真实 Workerd/D1。旧版使用上一轮已核验 SHA-256 的完整构建，新版使用最终 `index-CsRF2fr1.js`。两次都是 1,001 个合成 token events、双设备、90,000 Tokens，每个 v3 请求额外延迟 120 ms。两次是相同规则生成的独立合成用户，不是线上数据。

| 观测项 | 旧完整镜像页面 | 最终在线页面 |
| --- | ---: | ---: |
| 首 5 秒启动的 v3 API 请求 | 28 | 8 |
| 其中镜像请求（read/manifest/entities 等） | 19 | 0 |
| 上述请求的实际解码响应体 | 1,193,201 bytes | 6,668 bytes |
| 记录时窗内 IndexedDB put | 4,044 | 0 |
| 主统计 90K 的首次可见 DOM 时间 | 870.2 ms | 705.6 ms |
| JS 原始产物体积 | 938,842 bytes | 913,958 bytes |
| CSS 原始产物体积 | 48,952 bytes | 48,509 bytes |

这个样本的接口请求数减少约 71.4%，解码响应体减少约 99.44%。镜像之外旧版还发了一次 sync/status；新版也不需要它来初始化页面。所有 fetch/IndexedDB 观测钩子均实际执行成功，最终样本没有浏览器运行错误。首次从旧版切到新版时另观察到一次旧数据库删除；最终独立样本连数据库打开都没有发生。

**时间值不能解释为线上提速百分比。** 旧版 JS 实际传输约 289 KB，最终样本的 JS 只有 300 bytes 的传输记录，存在静态资源缓存差异。上述时间各为一次观测，不是相同静态缓存条件下的多轮统计。IDB 精确计数对应整份页面报告时窗，不伪称只有首 5 秒；首 5 秒的字节数是该时窗启动请求最终收到的解码响应字节，不是压缩后的网络字节。

原始文件、产物 hash、重复 report 去重方法与中间候选分类见[浏览器汇总](../../artifacts/cloud-online-20260913/browser-summary.md)和[机器可读结果](../../artifacts/cloud-online-20260913/browser-summary.json)。仅 `cua-baseline-cold.json` 与 `cua-final-latest.json` 参与最终对照。复现入口见[本地夹具](../../experiments/cloud-online-20260913/README.md)。

## 服务端清理瓶颈

隔离 D1 夹具中，100,000 条 v3_events 全部属于当前 epoch，没有可删除数据。原旧 epoch 查询每轮仍读取 300,001 行；将 `epoch <> active_epoch` 全局扫描改为从 domain 出发的两个索引范围后，每轮只读取 5 行。三次本地耗时从 25/24/25 ms 变为 2/3/2 ms，删除行数均为 0。

五张表的相同循环均使用现有索引，保留活动 lease、pending/running 构建保护及每表全局 LIMIT 1000；没有增加表、索引或迁移。规模测量只针对 v3_events，其他四表做执行计划与功能验证。大量被保留的旧 epoch 仍可能导致较多扫描，不把这个修复称为严格 CPU 预算。[报告与复现](../../experiments/cloud-online-20260913/cleanup-review.md)。
