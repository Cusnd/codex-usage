### F01 / F02：执行来源在恢复、保留副本时退化

两项均不是全局 Token 重复或消失；错误发生在已确认的“哪台设备执行”这一归属上。F01 保持设备 ID、Collector ID 和原始文件，只执行断开／重绑和重扫，新 generation 将记录标为 `observed_local`，覆盖此前 `local_append` 证据。F02 使用默认采集器读取普通原始文件副本；旧测试人为构造 `preserved` claim，不能覆盖真实默认采集器没有产生此 claim 的情况。

位置：[Collector 来源](../../server/collector/store.ts#L181)、[云端重算](../../cloud/src/v3/apply.ts#L31)、[源移除](../../cloud/src/v3/apply.ts#L112)。复现及期望见[功能反例 D01/D02](../../artifacts/acceptance-v3-20260912/domain-audit/cloud-probes.test.ts)、[批次证据](../../artifacts/acceptance-v3-20260912/domain-audit/production-collector-batches.json)。普通采集端断网重试不等同断开绑定；前者本轮通过，不能抵消 F01。

### F03：迁移最终正确，中间可见版本双计

合法弱身份输入总量为 100。旧导入器先上传，云端可见 100；新 Collector 上报后、完整 handoff 前，`mode=ready` 且 summary 返回 200；handoff 后才恢复 100。若两步之间网络中断，错误结果会持续可见。已有测试检查最终旧源退休，却明确容许中间两条事件，没有验证每个正常可读版本的总量。

位置：[迁移交接](../../server/sync-v3/migration.ts#L27)、[上传顺序](../../server/sync-v3/uploader.ts#L58)、[旧历史](../../cloud/src/v3/legacy.ts#L17)。证据：[D03](../../artifacts/acceptance-v3-20260912/domain-audit/cloud-probes.test.ts)、[失败日志](../../artifacts/acceptance-v3-20260912/domain-audit/cloud-probes.log)。

### F04 / F05：管理操作的行为边界

F04 的请求为 `PATCH /api/v3/devices/:id/history`、body `{"paused":true}`。路由外层允许 PATCH 后进入不核对方法的删除分支，返回 200，同时写入撤销与删除时间。应拒绝不支持的方法并保持历史。位置：[routes.ts](../../cloud/src/v3/routes.ts#L64)。这是 API 契约问题，不能写成“点击正常暂停按钮会删除历史”。

F05 在 `accountInterval=0` 时可持续存在：恢复后 `AccountSource.readLimits` 次数仍为 1，没有新额度上传，需要另行手动刷新。位置：[恢复同步](../../server/cloud-sync.ts#L449)、[额度刷新](../../server/refresh.ts#L70)。证据：[额度复现结果](../../artifacts/acceptance-v3-20260912/domain-audit/resume-quota-result.json)。没有真实调用 OpenAI 账户。
