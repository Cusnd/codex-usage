### RELEASE-01：交付与完成标准

- [ ] 分阶段交付：A 可发现性/定位/Agent 文档；B 分析路径和手机体验；C 后端连续采集与远程访问；D 私有同步。每阶段只公开已验证能力。
- [ ] 每项完成时，在对应详细文件的完成记录中记录实现文件或 PR、验证日期、实际结果和剩余限制，再勾选；已有历史验收不替代新行为验收。
- [ ] 文档修改检查相对链接、示例命令和中英文一致性。代码变更按 [CONTRIBUTING](../../CONTRIBUTING.md) 执行适用的类型检查、测试、构建和 smoke；只为新增边界补充有意义的测试。
- [ ] 浏览器验收使用 browser-control 技能和工具，不使用 Playwright；尽量先做 DOM/语义检查，公开截图仅用合成数据。
- [ ] 远程/同步以隔离测试数据验收认证、撤销、断网、后台恢复和数据新鲜度；记录实测环境，不把 HTTP 成功或桌面缩放当作手机实机验收。
- [ ] 发布前核对 npm 实际支持平台、Skill 安装结果、GitHub/npm/主页链接和新增配置的默认值；云端发布与 npm 发布分别记录结果及回退方式。

### RELEASE-02：通用云端发布自动化

目标：用户明确要求“自动发布”后，准备并上传版本内容，启动统一 GitHub 云端任务。云端负责检查、集成、发布与收尾，不依赖本机继续运行；普通提交不自动发布 npm。

- [x] 提供 release.yml 通用入口，接收版本号、任务分支和完整来源 SHA，替换固定版本的一次性流程。
- [x] 编排精确文件树 CI、任务 PR、发布 PR、标签、npm 发布验证和分支同步，复用现有 CI 与 OIDC 发布流程。
- [x] 记录阶段和链接，支持已有 PR、标签及成功发布的复用；提供启动与恢复说明。
- [ ] 完成首次实际版本的云端闭环验收，确认无需本机参与；本次实现不触发真实 npm 发布。

验收标准：以后无需为每个版本新增脚本或工作流；云端启动后自行完成发布，或保留明确的失败阶段和日志。操作入口见[项目工作流](../../.agents/workflow.md)。
