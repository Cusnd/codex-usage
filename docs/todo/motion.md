# 交互与状态变化的动画设计

[返回总体统筹](README.md)

工作项：MOTION-01。优先级：P1（高）。状态以总览为准；具体复选框和完成证据在本文件维护。

## 目标与执行顺序

为项目设计合理、合适且符合应用设计调性的动画。所有涉及交互、状态变化或可见变化的位置都应纳入评估，包括按钮点击；逐项判断是否需要动画，并说明理由，不将“全面评估”等同于“全部添加动画”。

严格按“盘点并形成汇总 → 结合应用调性设计 → 实现与验收”的顺序推进。首先交付需要应用动画的汇总及不采用动画的理由，再依据现有产品视觉、信息密度和使用场景确定动画语言。

本次只登记待办，不代表已完成全项目盘点、动画方案或实现验收。实施时应复核当前代码中的已有动画和未提交改动，避免重复建设；现有动画同样需要评估。

## 范围与依赖

覆盖全部页面、共享组件以及桌面和移动端交互。与 [UX-01](analytics-experience.md) 的分析路径和 [MOBILE-01](mobile.md) 的触控体验协调；盘点不依赖这两个工作项先完成。

## 待办与验收

### MOTION-01：先汇总，再设计，最后实现

- [ ] 盘点全部页面与共享组件的可见变化：按钮点击及 hover/focus/pressed、选择与切换、导航、筛选和日期变化、展开收起、弹层开关、提示反馈、加载/刷新/成功/失败/空状态、列表和布局变化、图表及数据更新；记录已有动画与缺口。
- [ ] 形成动画评估总表，逐项记录页面/组件、触发条件、变化前后状态、现有行为、是否需要动画、目的、理由、优先级及关联实现位置；保留不采用动画的判断和理由。
- [ ] 从评估总表提炼“需要应用动画的汇总”，明确覆盖范围、复用关系和实施顺序，作为后续设计的输入；在此汇总完成前不直接进入动画实现。
- [ ] 审视应用现有设计调性和核心任务，制定统一动画原则与规范：节奏、时长、缓动、位移/缩放/透明度、层级和编排；说明这些选择如何服务操作反馈、状态理解和阅读连续性。
- [ ] 为汇总中的每类场景制定具体方案，明确触发、进入/退出、完成反馈、连续点击、中断与反向切换、异步等待及失败恢复；给出可评审的关键交互示例，避免用统一淡入替代场景设计。
- [ ] 定义减少动态效果（prefers-reduced-motion）方案及键盘/触控行为，确保取消或减弱动画后状态反馈仍完整；明确高频数据刷新、大列表和图表动画的性能边界。
- [ ] 按汇总与设计方案实施并复用公共动画能力，逐项关联代码位置和实际效果；避免动画阻塞操作、推迟真实状态显示、造成布局跳动或持续干扰读数。
- [ ] 使用可用 CUA 工具在 Codex 应用内浏览器验收关键路径，覆盖桌面/移动布局、键盘/触控、减少动态效果、快速重复操作、加载失败及频繁数据更新；记录验证环境、结果与剩余问题，并回填评估总表。

#### 验收标准

交付全项目动画评估总表、需要应用动画的汇总、符合应用调性的动画规范和场景方案，以及对应实现与验收记录。所有盘点项均有采用或不采用动画的结论及理由；已采用动画可追溯至具体方案。交互反馈及时、同类行为一致，快速操作和异步状态切换不残留错误视觉状态；减少动态效果后仍能理解状态并完成操作。

## 待决策问题

动画的具体风格、参数、适用场景和实现方式，待盘点汇总及应用调性评估后确定。
