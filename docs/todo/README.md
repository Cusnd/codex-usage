## 总体目标与共同边界

产品定位候选：**帮助用户追踪、理解并随时查看 Codex 用量的本地优先分析工具。** 对外可以评估“Codex 用量可观测性”表达，但应明确覆盖用量与额度，不暗示具备完整性能追踪、行为原因诊断或计费账本能力。

六项特色全部进入规划：深度分析、Agent 团队感知、可视化探索、随时查看、本地优先与隐私控制、Agent 查询入口。

“24 小时查看”拆成三个可验收目标：

1. 电脑和采集服务在线时，即使没有打开网页，也能持续采集。
2. 手机、平板或另一台电脑经过认证后，可以查看最近采集的数据。
3. 原电脑关机后，仍能查看最近成功同步的统计；界面明确数据截至时间，不能承诺继续实时更新。

实现遵循现有 Node.js/TypeScript/Fastify + node:sqlite、React/Vite 基础，先定义 API 和数据契约，再扩展前端。优先单用户方案；不默认引入团队协作、计费系统、原生手机 App 或多设备总账。公开合成演示与个人远程数据入口保持隔离。

本目录是规划，不是远程访问或云同步已经可用的声明，不代表供应商已选定或服务已部署。GitHub Topics/主页、npm 在线版本、搜索排名、演示站部署状态及供应商能力尚未实时核查；旧讨论中的描述仅作历史线索，核查已列入详细待办。

## 维护约定

- 状态统一使用：未开始、进行中、阻塞、完成。阻塞时在详细文件记录原因和解除条件。
- 工作项编号保持稳定，移动文件不重新编号；详细复选框不复制到总览或根目录入口。
- 开始工作时更新总览状态；完成时先在详细文件记录证据、勾选任务，再更新总览。仅整理规划不算功能完成。
- 更新验收记录时注明日期、实际环境与限制；历史测试结果不自动沿用为新版本验证结果。
- 跨模块通用规则维护在本文件和 delivery.md；具体设计、任务和完成记录维护在所属文件。
