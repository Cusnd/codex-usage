## 已有诊断及不能省略的约束

48c 的 30 次测试按轮同时上传同一用户的两台设备。成功应用都会推进该用户的统一写入版本；较慢请求需要重新计算后再提交。观察到带 PDX 标记的 15 个请求中有 14 次 CAS 重试，ATL 标记请求没有重试。代码与样本支持“不同请求路径耗时加上正常并发竞争放大延迟”的判断；日志未记录每次 guard 失败的具体子句，CF-Ray 也不能单独证明 Worker 的执行位置。

首次功能交付时普通增量路径约有 13 次顺序 D1 往返。本次已对可靠自然来源事件跳过无用的人工归属查询，合并独立的版本／项目预读，并测量保存来源证据的 200 条记录场景。具体请求量及计时见新报告；这仍不能代替原先两设备并发 30 个新增输入的远端 P90 验收。

统一版本 guard 保护共享汇总和完整发布，不能为了降低耗时移除或退化成仅按设备检查。不得通过降低精度、弱指纹去重、提前报告 applied、减少应保留历史，或更改 30 次测试场景来制造通过结果。

Smart Placement／区域配置仅完成可行性讨论。中断后没有继续部署、预热或性能采样；后续是否采用须以实际位置和对照测量为依据。本轮按用户要求暂停该探索。

## 已修复的正确性问题

100k 查询先后出现过全版本扫描导致的慢速 HTTP 500，以及构建截中未完成编辑导致的快速 HTTP 500。查询索引路径、成本分页和独立源码构建已修正，48c 的完整云端结果逐字段核对通过。保留失败版本证据用于解释问题，但不将已经解决的 500 继续列为当前功能故障。
